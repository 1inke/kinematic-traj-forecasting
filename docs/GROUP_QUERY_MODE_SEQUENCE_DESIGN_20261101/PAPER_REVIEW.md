## 2. Group Query 的“组”到底是什么

第一阶段产生粗轨迹，第二阶段将其转成 anchor queries，经 query–query、query–agent、query–lane、query–time 等融合后生成细化轨迹。

训练时，不只建立一组 K 个查询，而是 G 组，每组各 K 个：

\[
\hat Y^{(g)}\in\mathbb R^{K\times T\times2},\qquad
L=\frac1G\sum_{g=1}^{G}L_g.
\]

关键约束：

1. 查询生成参数在组间有区别；融合与预测模块共享。
2. query–query 自注意力仅在各组内部计算，不能混成 GK 个查询互相竞争。
3. 每组独立选 winner 并接受监督。原文用最小 FDE 选 winner，SmoothL1 回归及置信度交叉熵；并非我们的 ADE+0.5FDE。
4. 推理固定保留主组，仍输出 K 条，不是在 G 组中用GT挑最好的一组，更不是 GK 并集。

因此，这不是语义分群、不是 MoE 的输入路由、不是三个独立模型集成，也不保证每组承担不同运动语义。它增加的是共享网络获得的训练责任路径。

## 3. Mode-as-Sequence 的“序列”是什么

序列轴主要是候选模式 k，不是未来时刻 t。

- ModeSeq：依次生成模式，当前模式与之前模式的信息交互，再结合场景。
- Parallel ModeSeq：用因果掩码处理模式token，在单次网络前向内形成单向模式依赖。
- 每条候选仍可一次输出完整未来轨迹；因此与本项目的**时间维非自回归**并不矛盾。
- 并行因果注意力不等于逐模式循环的数值复现，也不意味着同一层已经读取了前面模式尚未算出的最终轨迹。它首先是隐藏token层面的依赖。
- 原文还涉及迭代细化及模式重排。不能只增加一个三角mask就宣称完整复现该方法。

它与稀疏场景编码属于不同轴：编码端控制邻居/时间交互，解码端控制20个模式之间的交互。二者可以组合，但模式注意力本身增加计算，不能记为稀疏化节省的 FLOPs。

## 4. EMTA 值得研究，但不是无风险替换

EMTA 在满足匹配条件的模式中选最早匹配者；若没有匹配则回到最近者。原文同时使用对应的回归、唯一正例置信度监督和排序机制。它不是让所有好模式同时回归，也不是直接的几何互斥约束。

Table IV 同一“无后处理”设置：

|Mode-as-Sequence训练方式|soft mAP|MR|minADE|minFDE|
|---|---:|---:|---:|---:|
|WTA|0.4138|0.1502|0.5563|1.1498|
|EMTA|0.4231|0.1457|0.5700|1.1851|

**排序/漏检指标改善与 oracle 连续误差变差同时出现。** 这恰好提醒我们：本项目已有“coverage变好但minFDE或原成功保留变坏”的反例，不应为了采用新方法而降低1%保护标准。

本地后续 E 仅测试一个隔离的“早匹配责任分配”版本，不移植作者整套分类/排序损失，不训练旧 scorer；不能将其命名为原文 EMTA 完整复现。

## 5. 对我们已有结果的正确解释

最新离散动作实验已经监督**所有合法动作**的集合效用。H在tiny128上达到76/74/76覆盖，Native69，但变化组始终9/23，transition minFDE恶化约3.233%/3.233%/4.766%。这里存在效用目标与独立误差保护不一致及动作价值误估，不能直接套“只有winner有梯度，所以失败”的解释。

另一方面，历史 ContextK20 新解码头确有生成新好路径的能力：inner change 166→186/191/192；但丢失33/37/37个原成功窗，变化组minADE/FDE及加速度均值恶化。因此它是一个**有覆盖信号但不合格的机制参照**，不是可部署baseline。

本次选择回到可直接产生20条轨迹的小解码头，检验训练责任和候选交互，是一次明确的大分支切换；不是证明离散动作训练已被解释清楚，也不是恢复旧实验被阶段门禁止的蒸馏分支。

## 6. 本地适配结论

|论文机制|本地处理|原因|
|---|---|---|
|训练多查询组、推理固定主组|优先实测|最小改变训练机制，推理K20不增|
|组内独立监督、组间共享网络|保留|防止辅助组只贡献大候选并集|
|粗轨迹anchor与地图交叉注意力|本轮不加入|现有ContextK20不是该架构；一起加入会混淆因素，地图标定也未解决|
|模式间交互|条件第二阶段|必须区分一般交互收益与因果顺序收益|
|原文整套EMTA/分类/排序|不直接加入|原文存在oracle误差代价；多因素改变不利归因|
|递归生成20模式|不优先|串行延迟与轻量目标冲突；先测单次前向版本|

最终能成立的创新表述应依赖实测：**训练期分组监督与轻量候选交互，在固定候选预算下提高有效覆盖，同时不损害原生支持及运动学。** 目前这是待验证假设，不能写成已实现创新，更不能把这些已有文献机制本身声称为原创。
