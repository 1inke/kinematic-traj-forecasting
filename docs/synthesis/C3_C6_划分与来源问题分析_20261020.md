## 0. 结论先行

1. **457 是"边界带"，不是"全段污染"**。它全部落在 `students003` 的 19 帧（7.6 s）切分边界上，涉及 29 个 track；修它只需要动 CAL 一侧，FIT / inner / outer 一个窗口都不用改。
2. **"完整未来 12 点落入 FIT 区间 = 0" 是差 1 帧的技术性零**。FIT 最后区间止于 257，CAL 最早窗口的未来止于 258；这不是安全边际，报告不能拿它当"无泄漏"证据。
3. **比 457 更严重的是 C1–C6 口径查不到的第三类问题：同帧共存**。outer 有 1,009/1,035（97.5%）窗口与 FIT 在**同 sequence、同 start_frame**上共存（不同 track）；change 组 250/253。`C2=0` 的 track 互斥给出的是虚假隔离感。
4. **C6 不是"同 track 暴露"，是"同窗口暴露"**。outer 1,035/1,035、CAL 2,879/2,879 的 sample_id 原样出现在 native 的训练清单里。任何重划分都修不了这一点，只能换控制臂、重训或缩 claim。
5. **正确顺序**：先改 CAL（几乎零代价）→ 再把控制臂改成"同批 FIT-only 重训"（一次性的工程代价）→ 再重估 MDE → 才谈 S0 冻结。先冻 S0 等于把一个基于暴露 control 的功效数字写进预注册。

## 1. 事实（可复算）

### 1.1 四个划分的真实结构

| 划分 | 窗口 | track | change 窗 | change track | 覆盖序列 | 场景族 |
|---|---:|---:|---:|---:|---|---|
| FIT | 18,909 | 689 | 4,725 | 337 | 6 段 | university / zara / hotel |

| outer | 1,035 | 191 | 253 | 68 | 6 段 | 同上 |

- 另有 **4,112 窗（change 935）注册但不在任何划分**：28,791 − 24,679。报告里"注册 28,791 / 科学人口 24,679"指的就是这批。
- 四个划分都是**同一批 6 段录像的时间/人员切分**，不存在"未见场景"。C5 的"outer 来自 FIT 已有场景族"是准确描述。

### 1.2 457 的构成：一条边界带

- FIT 的 `students003` 窗口 start ∈ [0, 238]，最大帧区间 [238, 257]。
- CAL 的 `students003` 窗口 start ∈ [239, 376]——它是同一段录像的**时间续段**。
- 29 个 FIT∩CAL 共享 track 全部在 `students003`。
- 457 个"CAL 与 FIT 时间交叠"的窗口 = CAL 中 start ∈ [239, 257] 且 track ∈ 那 29 个；**change 130**。
- 这 29 个 track 在 CAL 里一共有 **1,149 窗（占 CAL 39.9%）**，但只有 457 窗在时间上交叠；另外 692 窗是"同一人、更晚时间"（start 258–357），不构成标签重复，只构成 track 层面的不独立。
- 另外两对跨划分 track 也全在带内：inner∩CAL 2 track / 6 窗（start 239–243）、outer∩CAL 1 track / 12 窗（start 239–250）。

### 1.3 "contained = 0" 是一帧之差

- CAL start = 239 → 未来区间 [247, 258]；FIT 最晚区间 [238, 257]。
- 258 > 257 ⇒ 没有"整段未来被单个 FIT 区间包含"。这就是 `entire_future12_contained = 0` 的全部来源。
- 同一批窗口里有 **295 窗（change 86）** 的未来与 FIT 相交。也就是说同一段真值轨迹以"FIT 的 future"和"CAL 的 future"两种身份同时存在。
- 推断：这个 0 不能写进任何"无泄漏"论证。

### 1.4 C1–C6 覆盖不到的第三类：同帧共存

统计口径：评价窗口在 FIT 中是否存在**同 sequence、同 start_frame、不同 track** 的窗口。FIT 侧剔除 `ambiguous_track_time` 的窗口（101 个），因此这些命中是可信下界。

| 划分 | 有同帧 FIT 邻居的窗口 | 占比 | change 组 |
|---|---:|---:|---:|
| inner | 1,761 / 1,856 | 94.9% | 464 / 497 |
| outer | 1,009 / 1,035 | 97.5% | 250 / 253 |
| original_CAL | 0 / 2,879 | 0% | 0 |
| CAL v1.1 | 0 / 1,620 | 0% | 0 |

- 含义：outer 是"同一时刻、同一人群、不同行人"的留出，不是"未见场景/未见时段"的留出。
- 对主线 A（用 FIT 轨迹统计 cell/heading 先验）：评估窗口的同帧邻居的完整未来就在 FIT 里，`track 互斥` 与 `leave-track-out` 都挡不住。DESIGN_AB 的 `P-static` 在 outer 上不成立，`P-causal` 不是"到 S4 再换"，而是 S2 就必须用。
- 对任何用 FIT 统计做标准化 / 邻居编码 / 场景统计的组件：同样成立。
- 这一项不在 C1–C6 里，是审计口径的缺口，不是审计执行错误。

## 2. 三个问题必须分开处理

| 编号 | 问题 | 性质 | 重划分能解决吗 | 正确处置 |
|---|---|---|---|---|
| **P1** | CAL 与 FIT 的 457 窗时间交叠 | 真值标签重复 | **能** | 改 CAL 一侧，FIT 不动 |
| **P2** | outer/inner 与 FIT 同帧共存 | 上下文信息通道 | **不能**（除非换评估时段） | 改方法构造（P-causal / 共现 purge）+ 改 claim 边界 |
| **P3** | native 及 encoder 已见过 outer 与 CAL | 模型暴露 | **不能** | 换控制臂 / 重训 / 缩 claim |

把 P2、P3 当成"划分问题"去修，会得到"改了 split 但结论仍然不成立"的结果——这是本轮最需要避免的误判。

## 3. v1.1 划分提案

### 3.1 候选与代价

| 方案 | 做法 | CAL 窗口 / change / track | FIT 变化 | 训练作废范围 | C1/C2/C3 | 时间交叠 |
|---|---|---:|---|---|---|---|
| **A** CAL 侧 track 互斥 | CAL 去掉 FIT∪inner∪outer 的共享 track（32 个） | **1,712 / 444 / 79** | 无 | 0 | 全 0 | 0（同 track 口径） |
| **B** CAL 侧 track+时间互斥 | A 再丢掉 start ≤ 257 的带内窗口 | **1,620 / 443 / 77** | 无 | 0 | 全 0 | **完全 0** |
| C FIT 侧 track 互斥 | FIT 去掉 29 个共享 track | 2,879 / 700 / 111 不变 | 18,003（−4.8%） | 全部历史训练/checkpoint/缓存 | 全 0 | 非 0（567 窗） |
| D 双缩 | C + B | 1,620 / 443 / 77 | 18,003 | 最贵 | 全 0 | 0 |

### 3.2 推荐 B

理由（按重要性）：

1. **CAL 没有被任何历史结果使用**（PROTOCOL §2.2 封存），改它不追溯作废任何东西。
2. **FIT 是所有历史基线与冻结缓存的锚**；改 FIT 会让 287 个历史目录与 `native20/KIN/HGB` 全部降级为"不可比"，成本远大于收益。
3. B 只损失 1,259 窗（43.7%）与 257 个 change 窗（36.7%），换来 **C1/C2/C3 全 0 + 时间完全不交叠**，且 outer/inner 一个窗口不动。
4. 残余的 92 个"带内、非共享 track"窗口只值 1 个 change 窗——丢掉它几乎免费，没有理由留在里面。

### 3.3 代价要说清楚

- CAL change 人口从 700/73 track 降到 **443/50 track**；S4 的 MDE 会进一步变大。
- 这不是新增障碍：D-0 已显示 outer（253 窗 / 68 track）的 MDE 就在 4.58–6.82 pp，CAL 从来不是"能救回功效"的样本量。
- CAL 仍然是**单录像（students003）**，v1.1 不会让它变成场景泛化集。S4 只能支持"同一录像后段时间"的确认。

## 4. C6 来源处置

### 4.1 四个选项

| 选项 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **1** 控制臂同批 FIT-only 重训（B0 / CTRL） | 旧 native 降级为"历史参考、已暴露" | 一次 loader 改造 + 3 seed × ~12 min | **推荐主路径** |
| 2 clean encoder | 用 FIT-only 重训 encoder，再冻结 | 与 1 同量级 | 需要"整模泛化"claim 时必做 |
| 3 缩小 claim | 只声明"在固定、已暴露表征上的 head/prior 增益" | 0 | 只作为副结论，不能当主结论 |
| 4 换外部数据 | — | 不可行：native 见过全部 6 段录像 | — |

### 4.2 为什么"只重训 newhead"不行

- newhead 训练在暴露 encoder 上，treatment 与 control 共享同一暴露通道，对比是 common-mode——**相对结论**可以保留，**绝对性能和"泛化"表述**不成立。
- 更具体：G1（运动学 ≤1.01× native）、G3（Q-winner 相对 harm ≤3%）的参照都是 in-sample native，阈值本身不可解释；G4（丢失 native 好窗口 ≤10%）同理。
- 因此护栏需要在"同批重训的 control"上重新定义参照，不能沿用 D-0 的 native 数值。

### 4.3 对 D-0 / MDE / S0 的连锁

1. control 改为每 seed 重训 ⇒ D-0 里"同一 native 复制三次"的 zero-variance seed 分量假设失效。
2. seed 方差分量变大 ⇒ MDE 变大 ⇒ 现在 S0 里写的 `expected_effect_pp = 4.0` 更可能低于 MDE。
3. 结论：**先定 control 设计 → 重做 D-0（或至少重估 seed 方差）→ 定 MDE → 再 S0**。
   反过来（先 S0 后改 control）会把一个不可比的功效数字锁进预注册。

### 4.4 成本量级

- h3 30 epochs 实测 722 s/run（本机）；3 seed 约 0.6 GPU·h；m2/v2 同量级。
- 真正的成本不是算力，是 loader 必须支持 `train = FIT 索引子集`，并把每 checkpoint 的训练 ID manifest 落盘（现在 C6 的"per-checkpoint provenance 未证明"就是缺这个）。

## 5. 对判定链的影响

| 环节 | 现状 | v1.1 + 新 control 之后 |
|---|---|---|
| PRIMARY 人口 | outer change 253 / 68 track | 不变（outer 不动） |
| PRIMARY 参照 | 暴露的 native（in-sample） | 同批 FIT-only 重训 control |
| 偏置方向 | control 偏强 ⇒ Δ 偏保守；但 control 无效 | 需要重新估计，历史 A−native / B−native 不能当先验 |
| G1 | 对 in-sample native 的 1.01× | 对同批 control 自身重新定义 |

| MDE | 4.58–6.82 pp（固定 native 假设） | 待重估；大概率更大 |
| S4 | CAL 700 / 73 | 443 / 50，且只能支持"同录像后段"确认 |

一个容易被忽略的推论：如果 treatment 仍建立在暴露 encoder 上，那么 **Δ 的符号仍然可信（同通道对比），但 "提升来自先验/结构" 的机制归因必须由 A-prior vs A-shuf 这类同容量对照来承担**，不能由 A vs native 承担。
