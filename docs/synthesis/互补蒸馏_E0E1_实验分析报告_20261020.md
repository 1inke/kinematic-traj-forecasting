# 互补蒸馏方向验证实验分析报告（E0 + E1）

日期：2026-10-20｜分析对象：2026-10-20 当天完成的两组新实验
范围：E0（干净人口 oracle 互补机会重估，零训练）+ E1（五臂学生蒸馏筛选与三 seed 确认，GPU 训练）
一句话结论：**机会被干净地证实存在（+8.3pp，CI 不跨 0），但当前规模的模型学不会它；方向按预设纪律在筛选规模停止。**

---

## 1. 背景与问题

项目已知：native K20 与 KIN K20 候选池存在互补（oracle 可组出更好的 20 条），但所有不用真实未来（GT）的选择器方法都失败了（K1-S 误拒 82% 有益动作）。新思路：不做"生成后挑选"，改为**训练时学习互补、推理时直接生成**——把教师池的互补性通过"保留＋补全"两类集合级监督蒸馏进单个轻量 K20 学生模型。

两个问题按顺序必须回答：

- **Gate ①（E0）**：排除上游数据污染后，互补机会还存在吗？（2026-10-20 审计发现底座接触过部分验证数据，旧的 +6~9pp 数字存疑）
- **Gate ②③（E1）**：一个学生模型能把这种互补学进去吗？"保留＋补全"分解是否优于普通蒸馏？

## 2. E0：干净人口上的机会重估（零训练，54.8 分钟 CPU）

**方法**：用作者当天冻结的 v1.1 划分（`qoder_work/v1_1/SPLIT_V1_1.json`，FROZEN_BY_AUTHOR），把 CAL 中与 FIT/inner/outer 共享 track 或时间重叠的窗口全部剔除，得到干净人口 **cal_v11 = 1620 窗 / 443 change 窗 / 77 track**（剔除 1259 窗 / 32 track 作为"暴露对照组"）。在两个人口上分别跑 K0-C oracle（用 GT 的贪心组合，仅作上界诊断），并首次利用 v1.1 的真实 track 标签做 **50 个 change-track 簇的配对 bootstrap**（20,000 次抽样）——此前 CAL 评测因身份占位符无法做区间推断（BLOCKED_IDENTITY），本次解除。

### 主结果（change 组完整成功数：同一条路径 ADE≤0.2 且 FDE≤0.4）

| seed | 人口 | native K20 | K0-C oracle | Δ | 相对幅度 | W 联合门 |
|---|---|---:|---:|---:|---:|:---:|
| 42 | **clean** | 146/443 | 182 | +36 | +8.1pp | True |
| 43 | **clean** | 146/443 | 180 | +34 | +7.7pp | True |
| 44 | **clean** | 146/443 | 186 | +40 | +9.0pp | True |
| 42 | dropped（暴露对照） | 97/257 | 117 | +20 | +7.8pp | True |
| 43 | dropped | 97/257 | 117 | +20 | +7.8pp | True |
| 44 | dropped | 97/257 | 116 | +19 | +7.4pp | True |

### Bootstrap 区间（Δcoverage，change 组）

| 口径 | 均值 | 95% CI |
|---|---:|---|
| **三 seed 平均** | **+8.27pp** | **[+6.47, +10.15]** |
| seed42 / 43 / 44 | +8.10 / +7.66 / +9.04pp | 下界均 ≥ +4.5pp |

### 质量细节

- 变化组 minADE 0.2549 → 0.2336~0.2378（**−6~8%**）；minFDE 0.4488 → 0.3854~0.3946（**−12~14%**）；
- **lost = 0（6/6 cell）**：oracle 没有丢失任何原成功窗口；平均每次仅 0.33~0.50 次替换。

### E0 结论

1. 机会**不是数据污染的假象**：干净人口 +8.3pp，暴露人口 +7.7pp，暴露没有放大机会；
2. 机会在更难的人口上不打折（clean 的 native 基数 33.0% 更低，绝对增量反而更大）；
3. 三个口径一致：outer（未除污）+6.3~9.1pp、CAL 全量 +8.0pp、cal_v11 干净 +8.3pp——**+8pp 是可稳定引用的上界**。

## 3. E1：五臂学生蒸馏（GPU，每臂约 15 秒）

**方法**：固定学生（kdec SharedTrunk + K20 query，57,432 参数，单次前向，推理无选择器）、固定预算（8 epochs / FIT 训练）、固定基础损失（WTA + 多样性），只改监督信号。教师 = 冻结 native/KIN 的 FIT 缓存，用 FIT 的 GT 标出"好候选"（合法训练监督）：

| 臂 | 监督 | 回答什么 |
|---|---|---|
| A | 仅基础损失 | 公平基线 |
| B | + 覆盖 union 全部好候选 | 普通集合蒸馏（排除"多监督就好"） |
| C | + 仅覆盖 native 成功窗的好候选 | 保留信号 |
| D | + 仅覆盖 native 失败窗的好候选 | 补全信号 |
| E | + 保留项与补全项独立加权 | 二者是否兼容且优于 B |

集合监督用单向 Chamfer（每条教师路径拉最近的学生槽位），不做槽位编号匹配、不平均互补路径、不冻结槽位。评估在 inner（与 FIT track 互斥），outer / cal_v11 未消耗。

### 筛选（seed42）：全部通过条件满足

E 取得最高 change good（161）、最高 rescue（45）、最低 lost（50）、最低 ADE/FDE，且 E>B、D.rescue≥C.rescue、C.lost≤D.lost 三条归因检查全过——理论模式完整出现。

### 三 seed 确认：**FAIL——seed42 的优势是噪声**

inner change 组完整成功数（N=497；native 参考 = 166）：

| seed | A | B | C | D | E |
|---|---:|---:|---:|---:|---:|
| 42 | 140 | 145 | 138 | 142 | **161** |
| 43 | 137 | 133 | — | — | 129 |
| 44 | 148 | 137 | — | — | 138 |
| **均值** | **141.7** | 138.3 | — | — | **142.7** |

- E−B = +16 / −4 / +1（符号跨 seed 翻转，均值 +0.87pp）；
- E−A = +21 / −8 / −10（均值 +0.2pp）；
- B−A = +5 / −4 / −11（普通蒸馏本身也不稳定优于基线）。

按预登记停止规则：**E 优于 B 的机制主张不成立，此路线在当前规模终止**，不进入 λ 扫描 / 加复杂度的小变体循环。

### 失败的两个机制解释（不是翻案）

1. **补全信号在训练分布中太稀疏**：FIT 的 8,051 个 native 失败窗中，仅约 26% 存在任何可教的 union 好候选（平均 0.26 条/失败窗）——E0 证明的机会集中在难窗，训练时学生很少见到可学的补全样本；
2. **学生容量不足**：inner change 上 native=166，最好的学生臂仅 161（且只在 seed42），多数臂低 20+——"保留 native 成功模式"本身已超出 57K 参数的容量。

## 4. 总体判定

| 关卡 | 问题 | 结果 |
|---|---|---|
| Gate ① | 干净条件下机会存在？ | **PASS**（+8.27pp，CI [+6.47,+10.15]） |
| Gate ②③ | 学生能学会？分解机制成立？ | **FAIL**（三 seed 确认不复现） |

**方向现状一句话：+8pp 的干净上界已被证实，瓶颈从"选择器"转移到"学生容量 × 信号密度"。**

若再试一轮（容量约 2 倍 + 可教窗过采样，A/B/E×3 seed，GPU <1 小时，主要成本在预登记），成功后的合理预期为 change 组 minADE −3~4%、minFDE −6~8%（约为 oracle 上界的一半）；再失败则建议正式关闭本方向，E0 的干净上界作为档案事实保留。
