# 【待执行】EXP-KINE-ANCHOR-ORACLE：机动模板能不能比现有锚点更好地覆盖真实未来？

- 类型：零训练检验。只用 CPU 和 NumPy，不用 torch，不训练，不做模型推理。
- 预计耗时：五折全跑完，普通笔记本 CPU 大约几分钟（含 3 个聚类 seed 和敏感性分析）。
- 在决策里的位置：它回答"方向 A（运动学解码）是否值得进入训练阶段"。解码最终怎么改，要等你分析完汇总的论文再决定。本实验只是其中一项依据。

## 1. 为什么要先做这个检验

方向 A 的想法是：运动模式不再表示"往哪个位置走"，而是表示"速度相对现在变成几倍、朝向转多少"。解码时用观测到的当前速度把它还原成轨迹。

**仓库里其实已经有过一次运动学解码的尝试**，见 `research_archive/05_generation_and_kinematic_refinement/KINEMATIC_DECODER_*_20261018` 和 `MODE_DIVERSE_KINEMATIC_20261018`。那批实验让解码器逐步预测速度、加速度，再积分成轨迹：
- 比"直接输出位置"的弱基线好；
- 但覆盖率一直卡在约 0.56，低于当时原生解码器的 0.60；加长训练、放宽限幅都没能突破。

教训是：**如果一种表示方式本身的上限就不高，花再多训练也补不回来。** 所以这次先不训练，直接问表示方式本身：同样 20 条模板，在不同坐标系里聚类，哪种能更好地覆盖真实未来？

和那批实验的区别：那次是"逐步积分速度和加速度"；这次是"按观测速度归一化的多模态机动模板"。两者针对的问题不同，这次针对的是速度偏移和减速。

## 2. 比较的四种模板（都不训练网络）

为了公平，四种模板用**完全相同的形状**，也就是 B0 的 h3 解码器的形状：
- 在朝向归一化的坐标系里取第 4、8、12 步三个关键点，再线性插值成 12 步；
- 插值矩阵直接照抄 B0；
- 朝向归一化和 B0 完全一致：用最近 3 步位移定朝向，位移不超过 0.03 m 时默认朝向 (1, 0)。

四种模板只有"模板所在的坐标系"不同：

| 臂 | 模板表示 | 对应什么 |
|---|---|---|
| **P** | 关键点的绝对位置（米） | 相当于 B0 的模板，但不带逐样本尺度 |
| **P_AUG** | 同 P，但先用 EXP-SPEED-AUG 的速度增强扩充训练轨迹，再聚类 | 回答"为什么不直接做增强" |
| **S** | 关键点位置 ÷ (v_eff × 0.4 s)，即"按当前速度走了几步" | 只做速度归一化，不改成机动坐标 |
| **K** | 每段（1–4、5–8、9–12 步）的速度比 ρ 和方向 φ | 方向 A 本体：机动模板 |

共同设定：
- 20 个模板在每折的训练部分上用 k-means 聚类得到。
- 每个测试窗口的 20 条候选，只由"模板 + 该窗口的观测速度和朝向"生成，**不看未来**。
- `v_eff = max(最近速度, V0)`，V0 = 0.3 m/s。这是一个按慢速步行设的先验下限，防止静止的人"速度比"失效。

**参考（不参与判定）**
- `REF_P_ORACLE_SCALE`：P 模板加"每个窗口用真值挑出的最佳缩放倍数"。它代表 B0 现有的"逐样本尺度"机制理论上最多能做到多好，用到了真值，只当上界看。
- 可选：已训练好的 B0 / AUG 模型的预测，只用来看模板和训练后模型之间差多少。

## 3. 数据和划分

- 标准 ETH/UCY 五折，数据和 EXP-156、FIVEFOLD 完全相同（`processed_data_diverse`）。
- 每折的训练集用 scene_tail 规则切成 95% fit 和 5% val，和 EXP-156 一致。
  - 模板只在 fit 上聚类；
  - **val** 看分布内表现，**test** 看跨场景表现（ETH 就是速度偏移的那一折）。
- 分组沿用以前的代码，逐字复制：
  - 机动标签与 EXP-ETH-SPEED / EXP-DECEL-DIAG 相同，其中减速+停止合称 `decel_stop`；
  - 速度三档按 fit 集的 p50 / p90 切分；
  - C0 变化组。

> 关于"干净规则"：这里确实用到了测试集，但**没有任何参数是看测试集选出来的**。V0、λ、K=20、关键点、增强参数、判定阈值在运行前全部固定（见 `code/kine_repr.py`、`code/kine_decide.py`）。敏感性分析只报告，不用于挑选。

## 4. 指标

- minADE20、minFDE20（米，两个最小值分别计算，和以前一致）；
- minFDE 的 p90；
- 可达率：minFDE ≤ 0.4 m 的窗口比例，表示"只需要小修正就能到达"。

所有臂都在同一批窗口上比较，并用 3 个聚类 seed（0、1、2）取平均。

## 5. 预注册判定（运行前固定，代码 `kine_decide.py`）

增益 g(X 相对 Y) = (Y − X) / Y，正数表示 X 误差更小。主比较是 **K 相对 P**。

| 检查 | 内容 |
|---|---|
| C1 速度偏移 | ETH 测试：minFDE 增益 ≥ 5%，且 minADE 增益 ≥ 3% |
| C2 相对增强 | 五折测试的 overall minFDE 等权平均：K ≤ P_AUG |
| C3 不伤其他折 | 每一折测试：minADE 和 minFDE 增益都 ≥ −2% |
| C4 分布内不变差 | 五折 val 平均：minADE 和 minFDE 增益都 ≥ −1% |
| C5 减速 | 五折测试合并的 decel_stop 组：K 的 minFDE 不大于 P，也不大于 P_AUG |
| C6 稳定 | ETH 测试：3 个聚类 seed 一一配对，K 都优于 P |

- **SUPPORT**：C1、C3、C4、C6 全部通过，并且 C2、C5 至少通过一个。表示机动模板有零训练证据，可以进入训练验证（另写实验文档）。
- **WEAK**：C3、C4 通过，ETH 测试 minFDE 增益 ≥ 2%，但没有达到 SUPPORT。表示速度归一化有一点作用但不够明确，可以作为 B（候选间优化）的附属设计，不单独立为主线。
- **NOT_SUPPORTED**：其他情况。方向 A 降级，解码以 B 为主。

5% 门槛的来由：EXP-ETH-DIAG 里只在测试时把速度缩回熟悉范围，训练好的 B0 误差就降了约 8%。如果模板层面连 5% 都不到，就不值得为它改解码器。

**归因（不影响判定）**
- K 相对 S：差距在 ±2% 以内，说明增益主要来自"速度归一化"本身，速度比加方向这种机动参数化不是必需的，以后可以直接用归一化的位置模板。K 更好，说明机动参数化有额外价值。
- S 相对 P：单独看速度归一化的作用有多大。

## 8. 局限（读结果时要记住）

1. **模板不是训练后的解码器。** 这里的候选只用了速度和朝向，没有用编码器的上下文，所以绝对误差会比 B0 大很多。只有各臂之间的相对比较有意义。
2. **模板层面的优势只是必要条件，不是充分条件。** 05 档的经验说明：表示方式好，训练后不一定更好。SUPPORT 之后还要真正训练来验证。
3. 机动坐标里，方向角在 ±180° 附近（往回走）会有跳变，k-means 求平均会不准。这种窗口很少，不做特殊处理。
4. λ = 1 表示"把速度减半，约等于转向 40°"，这是一个人为约定，所以单独报告了 λ = 0.5 和 λ = 2 的敏感性。
5. P_AUG 只增强了未来轨迹，因为模板不看过去。它对应的是"模板层面的增强"，不完全等于训练时做增强。
6. 如果 ETH 测试里减速窗口不到 20 个，报告会标"小样本"。C5 用五折合并的窗口，就是为了避免这个问题。
