### 0.2 要回答的问题

1. 在难情境（转向等）里，分类项是否也是塑造**每条候选位置**的主导力？
2. 如果是，它是把候选往真值方向拉，还是往外推？
3. 漏覆盖的真实未来落在哪里：方向错了、范围不够，还是终点对但路径形状不对？
4. （阶段二）切断这条梯度后，难情境的覆盖是否改变？打分质量要付出多少代价？

### 0.3 候选解释

| 编号 | 解释 | 由哪部分检验 |
|---|---|---|
| H1 耦合有害 | 分类项通过几何输入，把接近真值的输家往远离真值的方向推（让它们更容易被打低分），于是难情境里本来可能覆盖真值的候选被推开 | 阶段一 A2、A3；阶段二 S1 |
| H2 耦合无关 | 难情境里分类项的力相对几何项很小，覆盖不足由别的原因造成（信息不足、模板分布、WTA 分配） | 阶段一 A1；若成立就停止阶段二 |
| H3 耦合有益 | 分类项把几何推向"可区分"的形态，有助于打分（Top-1、校准），对覆盖影响不大或代价可接受 | 阶段二 S2、S3 |
| H4 信息而非梯度 | 打分头需要的是几何**信息**，问题不在梯度。切断梯度不伤打分，去掉几何输入才伤 | 阶段二 R-detach 与 R-nogeom 的对比 |
| H5 漏覆盖是方向或形状问题 | 与耦合无关，漏掉的是某些方向的模式，或终点对但路径形状不对 | 阶段一 B |

这些解释不互斥。

## 1. 【待执行】EXP-SCORE-COUPLING-DIAG（阶段一，零训练）

### 1.1 模型、数据与分组

- **模型：** B0@64 seed 42–46，`final.pt` 取 `ema`。加载方式、诊断前向 `h3_forward_diag`、逐窗分项损失 `per_window_loss` 和一致性检查，全部沿用 archive 21 的 `width_model.py`，不重写。
- **数据：**
  - 梯度分析（A）在 fit 上做，因为这是训练分布本身；
  - 漏覆盖分析（B）在 fit 和 dev 上都做；
  - 不做数据增强，使用 eval 模式。
- **分组（只用于分析）：**
  - 按 `maneuver_labels` 分组：
    - **难组（主分析）：** turn、turn_and_speed；
    - **难组（次分析）：** acceleration、deceleration、stop、start；
    - **对照组：** steady、stationary。
  - 另外报告 C0 的 change 组（变化分数 ≥ 0.5）。
- **A 部分的样本：** fit 中难组和次难组的全部窗口，加上 steady 随机抽 3,000 窗、stationary 随机抽 2,000 窗。随机种子 20261121，抽样索引写入输出。

### 1.2 A：每条候选上的力（检验 H1、H2）

对每个窗口、每个损失项 j（cls、reg、endpoint、short、coverage、diversity），求锚点梯度 G_j,k,a = ∂L_j/∂rel_k,a，其中 a 取第 4、8、12 步。做法沿用 archive 21。另外定义几何合力 G_geom = 除 cls 以外五项梯度的**向量和**。

**候选的名次：** 按训练用的质量 q = ADE + 0.25·FDE 排名，分四档：

- r1：赢家；
- r2–3：最近的输家；
- r4–6；
- r7–20。

**A1. 主导程度。** 对每个组、每个名次档，计算

```
D = Σ‖G_cls,k‖ / Σ‖G_geom,k‖
```

求和范围是该组、该档的全部窗口和候选。另外报告 r2–6 合并后的 D。

**A2. 朝真值的拉力。** 对每个锚点，取指向真值的单位向量 u_k,a = (y_a − rel_k,a)/‖·‖，其中 y_a 是局部坐标系下第 a 步的真值；距离 < 1e-6 时跳过。定义

```
P_j,k = Σ_a ⟨−G_j,k,a, u_k,a⟩
```

梯度下降会沿 −G 移动，所以 P > 0 表示这一项把候选往真值拉，P < 0 表示往外推。按组、名次档、损失项报告 P 的均值，以及 P < 0 的比例。

**A3. 径向扩张。** 取单位向量 v_k,a 为"从 20 条候选在该步的均值指向 rel_k,a"的方向。定义 E_j,k = Σ_a ⟨−G_j,k,a, v_k,a⟩，正值表示这一项把候选往集合外推。按组、名次档、损失项报告。

**A4. 与漏覆盖的关系。** 只看难组，把窗口分为"已覆盖"和"未覆盖"两类：

- 已覆盖：存在同一条候选满足 ADE ≤ 0.2 m 且 FDE ≤ 0.4 m，即 J ≤ 1；
- 未覆盖：不存在这样的候选。

对每个未覆盖窗口，取 FDE 最小的候选，报告它的 P_cls、P_geom，以及"P_cls < 0 且 |P_cls| ≥ 0.5·P_geom"的窗口比例。已覆盖窗口取同一候选作为对照。

**注意：** 这是训练结束时的梯度快照，只看方向和比例，不看绝对大小（局限同 archive 21）。

### 1.3 B：漏掉的真实未来在哪里（检验 H5；不论 A 的结果如何都做）

对难组里 J 未覆盖的窗口（fit 和 dev 分别统计），在局部坐标系下比较真值和 20 条候选，每个窗口归入下面第一个满足的类别：

| 类别 | 判据 |
|---|---|
| 形状错 | 存在候选的 FDE ≤ 0.4 m，但它的 ADE > 0.2 m（终点对，路径不对） |
| 范围错 | 真值终点位移 ‖y12‖ ≥ 1.0 m；在真值方向 ±15° 的扇区里，存在终点位移 ≥ 0.3·‖y12‖ 的候选；但最近的这类候选径向差 > 0.4 m |
| 方向错 | 真值终点位移 ≥ 1.0 m；±15° 扇区里没有终点位移 ≥ 0.3·‖y12‖ 的候选 |
| 近距 | 真值终点位移 < 1.0 m（方向不稳定，单独列出） |

每个类别报告：

- 窗口比例；
- 纵向误差和横向误差的均值，取最近候选；
- 最近候选的概率和概率名次；
- 对"方向错"的窗口，报告真值方向相对观测朝向的角度分布（30° 分箱）。

### 1.4 统计方式（A 和 B 都适用）

- 每个 seed 单独计算。"成立"指 5 个 seed 中至少 4 个满足。
- dev 上所有分组比例和均值，都按**轨迹**做聚类 bootstrap：每次有放回地抽轨迹，重复 2,000 次，报告 95% 区间。fit 上也报告这个区间。
- 每个分组都报告窗口数、轨迹数，以及前 10 条轨迹所占的比例。

### 1.5 预注册的描述性标记

| 标记 | 判据 | 支持 |
|---|---|---|
| **K1 CLS_DOMINATES_HARD** | 在 fit 难组主分析中，r2–6 的 D ≥ 1 | 分类项是难情境里塑造近邻输家的主导力（反对 H2） |
| **K2 CLS_PUSHES_AWAY** | 在 fit 难组主分析中，r2–6 的 P_cls 均值 < 0，且 \|P_cls\| ≥ 0.5·P_geom 的均值；同时轨迹 bootstrap 区间不含 0 | H1 |
| **K3 UNCOVERED_BLOCKED** | 在 A4 的未覆盖难组窗口中，"P_cls < 0 且 \|P_cls\| ≥ 0.5·P_geom"的比例 ≥ 50%，且比已覆盖窗口高至少 15 个百分点 | H1 和漏覆盖有关 |
| **K4 STEADY_CONTROL** | 在 steady 组，r2–6 的 D < 0.5 | 只是对照：说明耦合主要在难情境起作用，而不是处处都起作用 |

B 部分只做描述，不设标记。

### 1.6 阶段二的触发规则（运行前写定）

- **K1 和 K2 都成立：** 进入阶段二。
- **只有 K1 成立：** 分类项是主导力，但方向不确定（不推开也不拉近），仍进入阶段二，因为需要因果检验来确定它的净效果。
- **K1 不成立：** 不做阶段二。结论是在难情境里耦合不是主导机制，下一步依据 B 部分的类别分布另做诊断。

## 2. 【待执行·有条件】EXP-SCORE-COUPLING-PROBE（阶段二，因果检验）

**只在阶段一触发条件满足后执行。**

### 2.1 设置

- **底座：** archive 18 的冻结缓存。它保存了 B0@64 seed42 交给 h3 解码器的编码器 token：目标的全部 8 步和邻居的最后 1 步，形状 [9, 8, 96]，以及有效遮罩和坐标【已核实：archive 18 `IMPLEMENTATION_NOTES.md`】。前置检查：用缓存 token 跑原 h3 解码器，输出必须与 B0 seed42 的保存预测逐窗一致（误差 ≤ 1e-4，FP16 存储带来的误差另行报告）。
- **训练对象：** 只训练 h3 解码器，从头初始化，初始化方式与 `make_model` 相同。编码器 token 固定。
- **训练配置：** 与 B0 相同：
  - 损失用 `loss_value`（ModeQueryLoss + 0.2 软覆盖）；
  - AdamW，lr 2.5e-4，权重衰减 5e-4，cosine 调度，1 轮 warmup；
  - batch 64，64 轮，固定最终 EMA，衰减与 B0 相同；
  - **无法做数据增强**，因为 token 是固定的。这一点与 B0 不同，三个臂一致，只影响和 B0 的绝对比较。
- **三个臂**（参数量完全相同，只改打分头的几何输入）：

| 臂 | 打分头输入 | 检验 |
|---|---|---|
| R-couple | (mode, rel)，与 B0 相同 | 基线；也检验冻结框架能否复现 B0 |
| R-detach | (mode, rel.detach())，信息相同，没有梯度 | 梯度耦合的作用 |
| R-nogeom | (mode, 0)，几何位置填零 | 几何信息对打分的价值 |

- **seed：** 每个臂 3 个（0、1、2），共 9 次训练。

### 2.2 指标（都在 dev 上；必要时同时报告 fit）

- **主指标：** minADE/minFDE @ K=20，分别报告总体、难组主分析和各对照组。
- **覆盖：**
  - J 覆盖率；
  - HPD90 覆盖率，用 archive 20 SET-CALIB-DIAG 的同一套代码和核宽度。
- **集合几何：** 按观测分组的等权终点散布中位数，用来和 archive 21 F 部分的现象对照。
- **打分质量：**
  - Top-1 ADE/FDE；
  - 赢家的负对数概率，即 −log p(赢家)；
  - "该候选为好候选（J ≤ 1）"概率的 ECE，用 10 个等宽箱。
- **复核：** 在 R-couple 和 R-detach 上重跑阶段一的 A1、A2，确认 R-detach 中 G_cls 对几何的分量为 0，并观察几何合力的变化。

### 2.3 统计方式

- 各臂按 seed 编号配对：R-detach 的 seed 0 对 R-couple 的 seed 0，依此类推。
- **信号：** 3 对差值方向一致，并且平均差值的绝对值 > 2·SD/√3，其中 SD 是 R-couple 三个 seed 之间该指标的标准差（规则沿用 archive 10）。
- 分组结果另外报告轨迹 bootstrap 区间。
- 这些都只是描述性筛选，不是正式显著性检验。

### 2.4 预注册判定

| 标记 | 判据 | 支持 |
|---|---|---|
| **S0 FRAME_OK** | R-couple 三个 seed 的 dev 总体 minFDE 在 B0@64 seed42 的 ±5% 内 | 冻结框架可用。不成立时，S1–S4 只能作为框架内的相对比较 |
| **S1 COUPLING_HURTS_HARD** | R-detach 相对 R-couple：难组主分析的 J 覆盖率提升有信号，且难组 minFDE 不变差；总体 minADE/minFDE 变差 ≤ 1% | H1（耦合造成伤害） |
| **S2 COUPLING_HELPS_SCORING** | R-detach 相对 R-couple：Top-1 FDE 或赢家负对数概率变差有信号 | H3（耦合帮助打分） |
| **S3 GEOM_INFO_NEEDED** | R-nogeom 相对 R-detach：Top-1 FDE 或赢家负对数概率变差有信号 | 打分需要几何信息（支持 H4 的前半部分） |
| **S4 WIDTH_ADAPTS** | R-detach 的 dev 近静止组散布中位数比 R-couple 小，有信号；且 R-detach 中"近静止组 < 稳定移动组"的顺序在 3 个 seed 上都成立 | 耦合是 archive 21 发现的"宽度不随情境变化"的原因 |

### 2.5 结果如何指导下一步（运行前写定）

| 结果组合 | 解读 | 下一步 |
|---|---|---|
| S1 成立，S2 不成立 | 耦合伤害难情境覆盖，切断后打分不受损 | 机制得到因果证据。方法方向是"打分与生成如何交换信息"，例如打分只读几何，而几何只服从覆盖目标，或者设计一种有原理依据的交换方式。**先查文献**：如果 detach 已是常规做法，创新点就只能来自机制分析和在此基础上的新设计，不能来自 detach 本身 |
| S1 和 S2 都成立 | 两难：耦合同时伤害覆盖、帮助打分 | 方法需要同时满足两边，例如两阶段目标或分离的表示。这是更有研究价值的结构问题 |
| S1 不成立，S2 成立 | 耦合有益（H3） | 保留现状。难情境的覆盖问题去 B 部分找原因 |
| S1、S2 都不成立 | 冻结框架下耦合的净效果可以忽略 | 停止这条线，记录为"机制存在但不重要" |
| S4 成立 | 宽度现象由耦合造成 | 写入分析章节；不单独作为方法动机（静止窗口只占总 FDE 的 3%–8%） |
| S0 不成立 | 冻结框架偏离 B0 | 结论只能当作相对比较。若 S1 成立，需要端到端复核（另立实验） |
