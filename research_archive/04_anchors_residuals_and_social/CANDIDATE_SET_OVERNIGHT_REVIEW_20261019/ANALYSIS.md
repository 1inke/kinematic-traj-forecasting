# 联合候选集合过夜实验：数据复核与研究判断

日期：2026-10-19。对象：`CANDIDATE_SET_JOINT_FEASIBILITY_EXEC_20261018/OVERNIGHT_REPORT_20261019.md`。

## 结论先行

**这是一次有价值的分支定位，但不是模型突破：现有 native20＋KIN20 池中，存在满足质量、成功保留和运动学约束的 K20 集合；当前不用 GT 的选择器还不能可靠识别这些集合。**

因此，“池中完全没有可用答案”不能解释本次失败；但“只是接受门太保守，校准一下即可解决”也没有被证明。更准确的判断是：**有利替换的识别、组合后的质量预测、错误替换的拒绝和停止决策共同存在缺口。**

本轮只读分析与 CPU 保存数据重算，没有训练、加载模型、重新生成候选、查询旧进程或启动自动实验。旧文件未改。

## 2. 最重要的正结果：安全且有效的等预算集合确实存在

K0-C 是知道 GT 的贪心策略，不是可部署模型。它从 native20 开始，仅作符合注册约束的 native→KIN 替换。

### outer 变化组：253 个窗口，三个 seed 为42/43/44

| 方法 | 完整好轨迹覆盖数 | minADE（m） | minFDE（m） |
|---|---|---|---|
| native20 | 110 / 110 / 110 | .249147 / .249147 / .249147 | .429378 / .429378 / .429378 |
| K1-I：单候选代理监督 | 107 / 120 / 107 | .347267 / .317003 / .333443 | .697447 / .609817 / .656072 |
| K1-S：集合边际监督 | 113 / 113 / 111 | .252874 / .258521 / .256030 | .451054 / .466126 / .457093 |
| K0-C：GT oracle | **126 / 133 / 127** | **.236645 / .232437 / .231093** | **.390795 / .384533 / .391509** |

完整好轨迹始终指**同一条候选**满足 ADE≤.2m 且 FDE≤.4m；表中 minADE/minFDE 是另外的集合 oracle 指标，二者可以来自不同候选，不能拼成一条合格轨迹。

K0-C 三 seed 平均变化组 ADE 降 **6.32%**、FDE 降 **9.42%**；变化覆盖增加16/23/17个窗口，分别增加6.32/9.09/6.72个百分点。outer 全体覆盖625→716/717/720，原成功丢失均为0。

本轮复算 K0-C 的四个 split × 三 seed 全部 W 通过，五运动学门通过，原成功丢失0。original_CAL 变化组700窗口：243→**299/297/302**，平均 ADE/FDE 分别降低6.71%/11.78%。这是比“只降低误差、却牺牲安全”更强的可达性证据。

**但证据边界必须保留：**它证明在这些已观察 GT 上存在好集合，不证明仅凭过去观测就能学会选它，更不证明理解行人意图、真正未见场景泛化或部署成功。三个 seed 仍使用相同窗口；CAL 没有可靠 track CI。

## 3. 学习器到底进步在哪里，又失败在哪里

### S 比 I 少犯严重错误，但不是全面胜出

S−I 的变化组平均差为 ADE −.07676m、FDE −.19635m、minJ −.45425；原 family16 校正区间的上界均小于0。这支持“完整集合边际监督优于单条候选代理监督”在**连续误差**上的局部价值。

但是 S−I 全体覆盖反而平均 **−2.544个百分点**，校正区间为[−5.307, −.099]个百分点；变化覆盖差区间跨0。因此不能说集合监督在所有指标全面更好。

### S 仍没有超过 native 的联合标准

- outer 全体覆盖625→636/638/637，平均+1.159个百分点；原校正区间[+.192,+2.381]个百分点，是一个小的正信号。
- 变化覆盖仅110→113/113/111，平均+.922个百分点；校正区间[−1.167,+3.226]个百分点，不能称稳定改善。
- 三 seed 的变化 minADE **全部变差**，平均+2.67%；minFDE 全部变差，平均+6.69%。校正后的差值区间仍跨0，不表述为已确认总体显著恶化，但方向和硬门明确不合格。
- 变化组 rescue/lost 分别是3/0、5/2、3/2；seed43/44 丢失原成功2/110=1.82%，超过1%保留门。
- seed42 变化组 **speed p95 +1.483%**，五运动学门未全通过。逐窗口通过运动学门，不保证分组 pooled p95 通过。
- transition 误差保护同样有失败：seed42 ADE+2.487%；seed44 ADE+2.357%、FDE+3.945%。不能被全体平均稀释。

original_CAL 的 S 变化覆盖243→248/252/245，rescues10/14/6、lost5/5/4；平均 ADE/FDE **+4.01%/+3.81%**。这不是校准集合迁移成功，尽管 S 的 CAL 五运动学门通过。

上述区间引自保存 bootstrap，并核对了其全 outer track 有放回计权、共享 track 抽样后分组、三 seed 重采样和 family16 校正实现；本轮没有重新生成全部 bootstrap draws。

## 4. 原夜间报告的机制解释，需要怎样修正

### 4.1 “误拒82%”是真的，但不是完整的门控诊断

1007/1228=82.00% 的分母，是 **K0-C 实际挑中的有利动作，处于 K0-C 的状态轨迹**。它不是 S 部署轨迹中所有合法动作，也不包含全部负动作。

所以它证明漏掉许多 oracle 好动作，却不能单独回答：S 放行了多少坏动作？放宽门后精度是否仍足够？同一 GT-free 分数能否区分有利与有害替换？

原诊断已有反证：outer 1035窗口中，S 的 minADE 高于 native 的窗口数为 **25/56/34**，并不是只有误拒而没有损害。

### 4.2 不是简单“替换数量不够”

K0-C outer 平均只替换 **.375/.433/.379** 条，S 替换 **2.642/2.452/2.616** 条，即约6.5倍。oracle 的好结果来自少量合适替换，而非大量换入 KIN。

删除 S 的预测门、仅保留运动学门，平均替换约18条后，变化覆盖变成 **89/103/97**（native110）；变化 ADE 恶化约17%–25%，FDE约26%–36%。这说明预测门也在拦截有害替换，不能直接撤掉；同时并不证明找一个阈值就能解决排序和条件辨识。

### 4.3 几何排序的0.65%不是“99.35%动作有害”

8/1228衡量的是：在 oracle 所处状态上，几何规则的 top1 是否**恰好等于该次 oracle 选中的那一对槽位**。可能存在其他同样有效的替换。因此应称“精确 oracle 动作 top1 一致率”，不是部署正确率。

GTF/GTF_REL 的最终覆盖与误差失败，才是这些具体几何规则不够用的直接证据；不能外推所有几何特征均无效。

### 4.4 有两个值得验证、尚未确证的学习瓶颈

1. **标签极稀疏。** S 的训练动作中 ∆ADE/∆FDE/∆J 约91.2%–91.5%精确为0；∆coverage约97.5%为0。普通平方误差回归再按几个预测量的正负与极小正值排序，可能难以分清“真有边际价值”与“只是回归残差略正”。五个独立输出的期望值也不等于联合安全概率。尚未证明这是唯一根因。
2. **训练状态与实际决策状态不同。** 训练等量使用随机S0/S4/S12，S部署多数停在0–3次替换，成功oracle更接近native。seed42的L正例率在三状态为1.54%/6.86%/13.50%。状态分布偏移值得检查，但特征中已有native比例，不能仅凭分布差就断言模型必然无法适应。

因此建议将原报告的“主要瓶颈已定位为停机/接受过保守”改为：**当前证据定位到 GT-free 集合动作价值辨识及序列决策失败；误拒、误接受、排序与状态偏移均可能参与，尚未分离校准问题与信息/表征不足。**

## 5. 运行与报告质量问题

- 根 `RESULT_ANALYSIS.md` 开头仍写GO_K1=false/outer_incomplete、CAL无缓存；附录及后续文件已完成这些项目。是增量汇总陈旧，不应把旧头部当最终状态。
- 总报告把 HGB 扫参、K2、重训generator列入“已否方向”，不准确：这些是**未执行或未触发**，不是实验否定。K2 没有结果，不能说历史条件没有价值。
- `k1_exec/ARITHMETIC_AUDIT.json` 实际只写参数常数；根同名文件只有说明。名称不能代替独立重算。本轮补上核心质量/运动/W的数值复核，但不补做训练来源绑定或完整聚簇审核。
- 当前 `run_k1.py` 的续跑按文件存在判断：SEED_DONE存在就跳过、五模型存在就复用、split done存在就跳过，没有在这些分支核验模型/源码/训练行SHA兼容。结合报告记载过重复进程和中断，不应声称严格可审计的exact resume或完整训练因果链。本轮没有证据证明模型已经混用，但现有恢复机制不足以排除该风险；未来实验需补强，不能追写历史hash冒充当时锁源。
- K1未保存完整逐动作trace，只保存次数直方图和最终索引；因此不能仅靠这些文件还原全部部署状态下误接受率。
- CAL track全部为`?|−1`来自loader只填前25912条身份，属于**当前元数据连接缺失**，不是CAL真实只有一名行人。窗口点估计可算，track层统计不可伪造；需要从既有身份来源按sample ID补接后再谈相应区间。

## 6. 下一步应回答什么，而不是继续盲调什么

建议暂时保留现有生成池；不立即更换generator、不重复几何新颖度规则、不直接扫accept阈值，更不升级baseline。

优先用**FIT_train生成训练诊断、FIT_cal按track做独立检查**，回答一个窄问题：

> 在实际近native的状态和通过物理约束的合法替换中，现有GT-free信息能否区分“真正提高集合质量”的动作与“无用/损害原成功”的动作？

应同时报告：好动作召回、放行动作精度、原成功损失、含有至少一个好动作的窗口比例，以及相对于“保持原集合不动”的决策价值；按0/1/2/3次替换分层。接受门的几项预测和真实标签联合校验，不能只采oracle正例或只测精确slot命中率。

分支建议：

- 若有清晰可分性、只是风险分数偏移：再单独设计holdout校准的accept/abstain对照，所有阈值只用FIT_cal；outer不调参。
- 若近native状态的标签/分数都分不开：优先研究动作与受保护原生候选的相对关系、运动历史条件和集合表示，不能把校准当万能解释。
- 若只有FIT内可分而按track迁移消失：回到条件信息与泛化分支，而非换树深度或增加替换次数。

这是下一设计建议，本轮没有执行该诊断或启动训练。

## 7. 三次反方检查（同助手，非外审）

1. **反驳“池够了所以生成问题已解决”**：oracle知道未来；联合可达不是条件可学性，更不是未见分布的充分候选支持。保留生成改进作为后续可能分支，但当前无需用“池为空”解释失败。
2. **反驳“S已经学会集合选择”**：S改善了I的严重误差损害，却仍低于native联合标准，且S相对I整体覆盖下降。只支持局部机制价值。
3. **反驳“82%误拒就应放宽门”**：S比成功oracle替换更多；去门明显变坏。需要同时校准假阳性与假阴性，且先确认可分性。
