# 方案一（冲突门控图）与方案三（图-邻居协同自适应）全量基准评测与机制分析综合报告

> **评测目标**：在严格冻结当前模型权重（`F16 IR1 general seed1`）、不改变任何网络参数的前提下，评估**图交互机制**与**邻居选择/剪枝机制**对轨迹预测精度的调优极限。  
> **评测范围**：ETH/UCY 全量 5 大测试数据集（`eth`, `hotel`, `univ`, `zara01`, `zara02`，共计 **34,161 个样本**）+ 典型对冲瓶颈样例（Case 6802）+ 100 样本跨场景交互队列。  
> **基准对比对象**：
> 1. **基线 (Baseline)**：默认全连接空间距离自适应图 (`adaptive_kinematic`, $R=6.0\text{m}, \text{th}=0.35, k_{\text{min}}=2$)。
> 2. **方案一 (Scheme 1)**：纯图交互冲突门控 (`conflict_gated_adaptive`, $k_{\text{min}}=4, v_{\text{close}} \ge 0.30\text{ m/s} \lor d \le 2.8\text{m} \implies \text{th}=0.25$)。
> 3. **方案三 (Scheme 3)**：图-邻居协同自适应优化 (Co-adaptation: 静态邻居剪枝 $L_{\text{min}}=0.10\text{m}$ + 冲突门控图)。

## 1. 方案机制与数学表述

```
[原始场景行人序列]
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│ 方案三 前置选邻域 (Neighbor Domain)                         │
│ 计算每个邻居观测期轨迹长度: L_j = Σ ||p_j(t) - p_j(t-1)||    │
│ 判定准则: 若 L_j < 0.10m，则判定为静止路人/背景噪声并主动剪枝 │
│ 效果: 释放无效注意力槽位，避免静态路人带来假性空间引力       │
└─────────────────────────────────────────────────────────────┘
       │
       ▼ [筛选后的有效动态邻居池]
┌─────────────────────────────────────────────────────────────┐
│ 方案一 & 方案三 图交互域 (Graph Interaction Domain)          │
│ 1. 相对运动学度量:                                          │
│    距离: d_ij = ||p_i - p_j||                               │
│    接近速度: v_close = -d(d_ij)/dt                          │
│ 2. 动态自适应阈值门控:                                      │
│    threshold = 0.25 (当 d <= 2.8m 或 v_close >= 0.30m/s)    │
│    threshold = 0.35 (其余平缓/背离运动状态)                 │
│ 3. 强化最小连通度: k_min = 4 (保障强冲突邻居至少接入 4 条边)  │
└─────────────────────────────────────────────────────────────┘
       │
       ▼
[进入 Transformer 空间-时间交叉注意力编码器 (权重冻结)]
```

* **方案一：纯图交互冲突门控 (Conflict-Gated Adaptive)**
  不改变输入的邻居张量集合，仅通过接近速度与方位角对边连接关系进行几何门控，切断背向/无碰撞风险邻居的边，强化对冲迎面行人的注意力连通。
* **方案二：纯运动感知选邻 (Kinematic Selection)**
  探针实验中证明了**孤立生效定律 (The Isolation Invariance Theorem)**：如果图交互模块保持默认配置（$R=6\text{m}, \text{th}=0.35$），单纯改变前置邻居在张量内的顺序对预测结果为逐比特恒等（模型具有邻居置换等价性）。
* **方案三：协同自适应优化 (Co-adaptation)**
  将前置邻居的**静态路人剪枝 (Static Pruning)** 与**图交互冲突门控**协同耦合。剪枝后收紧有效节点数量 $N_{\text{valid}}$，使图构建完全聚焦于活跃互动群体。

## 5. 物理机制归因 (Observation vs Interpretation)

### 现象 1：HOTEL 数据集由负转正（扭亏为盈）
* **OBSERVATION**：在方案一中，HOTEL 的 minADE 上升 +0.32%，minFDE 上升 +0.55%；而在方案三引入静态剪枝后，minADE 转为 **-0.31%**，minFDE 转为 **-0.07%**，Top-1 FDE 下降 **-0.91%**，净胜局从 -32 翻转为 **+18**。
* **INTERPRETATION**：HOTEL 场景存在大量在建筑物前驻足停顿、低速交谈的静态路人。方案一仅根据距离连接，模型分配了过多的空间注意力给这些静态假目标；方案三将其剪枝后，有效释放了注意力，避免了静态平滑。

### 现象 2：ZARA01 街道对冲场景指标持续扩大改善
* **OBSERVATION**：ZARA01 的 minFDE 在方案一改善 -1.33% 的基础上，方案三进一步扩大至 **-1.46% (-4.63 mm)**，Top-1 FDE 降幅达 **-1.00% (-9.8 mm)**。
* **INTERPRETATION**：ZARA01 是典型的走廊型街道，人流对冲特征极强。方案三“剪去后方站立者 + 锁定前方迎面接近者”的组合机制完美贴合了通道行人的决策物理逻辑。

### 现象 3：ZARA02 与 UNIV 的边际差异
* **OBSERVATION**：在 ZARA02 中，方案一的 FDE 改善明显（-1.03%），而方案三的改善收窄至 -0.02%，minADE 出现 +0.35% 的微幅反弹。
* **INTERPRETATION**：ZARA02 包含了部分“停顿后刚起步”或“缓慢蠕动”的行人（位移刚好在 0.05m~0.10m 临界点）。全局固定的 $0.10\text{ m}$ 剪枝门限过于死板，在个别样本中产生了误伤，证明剪枝机制需要结合运动趋势自适应。

## 6. 科学证伪结论与当前盲区

### 已证伪与排除的假设 (WHAT IT RULES OUT)
1. **排除了“图交互改进仅对 Case 6802 单一特例有效”的假设**：  
   在包含数千样本的 ZARA01、ZARA02 以及全量 34,161 样本中，终点误差（FDE）改善系统性存在，证明冲突门控机制具有跨场景泛化能力。
2. **排除了“仅改选邻就能提升预测”的假设（孤立生效定律）**：  
   实测证明在默认图半径下，置换前置邻居顺序没有任何作用。邻居选择必须与图交互作用半径协同联动才能打破性能瓶颈。
3. **排除了“全连图越密越好”的假设**：  
   强制全连（Full Graph）会引发严重的注意力过度平滑（Oversmoothing），导致大量样本负迁移；冲突门控的精准裁剪是正向增益的核心。

### 尚未证明的盲区 (WHAT IS NOT PROVEN)
1. **全局单一固定阈值（$L_{\text{min}}=0.10\text{m}, v_{\text{close}}=0.30\text{m/s}$）尚未达到全局最优**：  
   不同数据集的拍摄视角、人群密度与基础流速差异显著，单一死阈值无法通吃所有场景。
2. **训练时协同效应尚未验证**：  
   当前所有实验均在完全冻结权重的推理端（Testing-time Graph Adaption）进行。若在训练阶段加入冲突门控掩码，模型是否能学出更强的互动表征仍有待验证。

## 7. 技术选型与下一步行动建议

### 选型结论与对比

| 考量维度 | 方案一 (纯冲突门控图) | 方案三 (图-邻居协同自适应) | 推荐评级 |
| :--- | :--- | :--- | :---: |
| **工程改造成本** | 极低（仅修改 `graph_builder._adaptive`） | 低（前置轻量剪枝 + `graph_builder`） | — |
| **街道对冲场景 (ZARA01/02)** | ★★★★★ (FDE 降 1.0%~1.3%) | ★★★★★ (FDE 降 1.46%) | **方案三略优** |
| **驻足密集场景 (HOTEL)** | ★★☆☆☆ (产生 +0.55% 负向反弹) | ★★★★☆ (扭亏改善 -0.07%, ADE -0.31%) | **方案三明显占优** |
| **实现风险与稳定性** | 极稳（不改变输入维度） | 稳定（需注意误剪起步行人） | **方案一更稳健** |

### 下一步决策建议

1. **若追求极简、零风险部署**：  
   直接采用 **方案一（冲突门控图）**，代码改动极小，全量推理速度无额外开销，街道场景 FDE 提升立竿见影。
2. **若追求更精细的多场景覆盖（尤其解决 HOTEL 类场景驻足干扰）**：  
   采用 **方案三（协同自适应）**，但需对剪枝机制进行一步自适应升级：将绝对距离阈值升级为**动量比率门限**（例如 $\frac{L_j}{\max(L_{\text{focal}}, 0.1)} < 0.1$），彻底消除慢速起步目标的误剪代价。
3. **针对高危冲突样本开展定向挖掘**：  
   将当前评测流程固化为**冲突挑战集评估工具 (Conflict Challenge Benchmark)**，专攻类似 Case 6802 这一类真正决定自动驾驶与机器人安全的高危长尾场景。
