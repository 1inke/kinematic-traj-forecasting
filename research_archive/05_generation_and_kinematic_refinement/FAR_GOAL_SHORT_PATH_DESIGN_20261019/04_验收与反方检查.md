## 2. 必过的实际预检

| 项目 | 必须验证的事实 | 不允许的替代说法 |
|---|---|---|
| 数据 | 同ID、坐标、单位、track、时间连续性、长标签掩码、区间归属 | 只核样本数量相同 |
| paired初始化 | 同seed所有参数/buffers/统计EXACT；A/B正常路径初始EXACT | 仅参数量相同 |
| GT隔离 | 修改GT/mask不改变相同权重的正常forward | 函数接收future后承诺“不使用” |
| 目标绑定 | goal与path共享slot；Q winner最低slot tie；goal mask分母正确 | 拼minADE/minFDE或独立goal winner |
| 几何 | NumPy独立重构12步、p12=z+a、dt/时点、真实H20目标不被强制塞进p12 | 只画平滑示意图 |
| 梯度 | 两臂实际GPU8个FIT batch，zero-last分阶段合法参数正且finite；共同loss NumPy标量一致 | 将解析零梯度的roundoff当有效连接 |
| FD | 固定非零小模型float64副本，eps=1e-4/1e-5；误差≤1e-6+1e-4×max绝对导数，winner活动面不变 | 搜eps/换样例求PASS；声称float32量化导数证明 |
| 真实恢复 | 两臂真实subset连续/中断2epoch全部参数/buffer/optimizer/RNG/history EXACT | 仅参数或loss近似相同 |
| 保存算术 | 实际128窗口两臂保存→独立完整质量/全SciPy聚簇/五motion重算 | 只用合成数据或检查status字段 |
| 来源 | 当前输入/代码/模型/统计/协议全SHA；坏source/坏output实际拒绝skip | 只检查done文件存在 |

自然初始某层零梯度是zero-last的预期，要按后续非零梯度阶段报告，不改初始化去制造结果。FD若活动面切换，标NONSMOOTH_CHECK_BLOCKED并解释；可以报告解析/自动微分局部值，但不得把未通过FD写成PASS。工程错误先保留失败来源，只在新目录修复并重新预检；科学变更需新版本预注册，不静默更新旧digest。

## 3. 反方检查一：是不是换了数据，才显得远目标好？

反驳：长轨迹更容易持续行走，只有完整20步标签的窗口可能本就更简单。延长未来还可能改变邻居成员或泄漏保留区间。

落实：两臂全部训练ID相同、辅助监督mask相同、ALL原12步主分母不变；固定原P2观测缓存，long label只连接目标人；新增跨分区区间mask排除但短期窗口保留。输出缺标签分布和legacy未来选择限制。若H0失败，不偷偷换时间长度或清除难例。

## 4. 反方检查二：是不是仅换了更强head，或process根本不使用远目标？

反驳：新架构与native不同，即便B胜native也可能只是新head效果。process可通过a抵消z，远目标aux下降而短期路径不变。

落实：A/B同结构、同参数、同初始路径；B−A是时间尺度对照，B−native只是实际质量比较。H2明确保存目标替换响应、抵消项、目标/路径误差，不用目标minK单项代表运动理解。固定basis限制了可表示运动，负结果只作用于当前参数化，不证明任何目标方法不可能。

## 5. 反方检查三：是不是更多救回掩盖更多丢失，或oracle被当成功？

反驳：过去已经出现rescues很多、lost更多；路径平均ADE变好但同一条完整good不存在；目标oracle和K40并集夸大部署能力。

落实：严格K20，主指标同candidate good/J；rescue、lost、native成功丢失率和每组五motion联合报告。H2 oracle仅冻结局部诊断，不部署、不称完整上界；主family校正与per-seed反例必须保留。未满足完整门不升级baseline，不自动scorer或新生成器。

## 6. 文档交付与后续实施的界线

本次交付可确认：设计逻辑、文件存在、内部链接、公式/配置一致性、旧约束纠正。不能确认：长标签全量可用、head实际参数量、GPU梯度/恢复、吞吐、六run效果及任何实验PASS。

最终实施报告应有四种清晰状态：COMPLETED_WITH_RESULTS、FAILED_WITH_EVIDENCE、INSUFFICIENT_DATA、NOT_EXECUTED。不能把“方案写好”“六个epoch文件存在”或“worker退出”当科学完成。
