# EXP-SPEED-AUG：ETH 单次宽范围速度增强

状态：条件实验，设计与代码已写；没有启动训练。先完成 EXP-ETH-DIAG，且其固定条件全部满足，才值得实际执行本项。程序不自动启动此训练。

## 问题与最小对照

目标是检查：保持当前 B0 训练过程不变，只扩大速度增强范围，能否降低 ETH 的整体和高速组误差？这也探索模型是否能在更大的运动尺度范围内稳定预测，但单次指标改善不能证明模型“真正理解了运动状态”。

只新训练一组 ETH B0，seed42，64 轮。对照复用原 `budget_eth_E64_s42` 的最终 EMA。使用原 ETH 95% scene_tail 训练子集 28791 窗，与对照训练索引散列完全相同；每轮 450 次更新，共 28800 次。

本项用 64 轮，是因为本机已有**同数据、同预算、同 seed 的 ETH B0**，可用一组新训练完成配对探索。沿用 128 轮会增加时间；直接训练 16/32 轮却拿 E64 对照，会把预算差混进增强效果。此处的 64 轮不代表重选了旧正式五折预算，也不表示已证明 32 轮不适合其他探索。

## 唯一有意改变的训练设置

| 设置 | 原 B0 | 本项 |
|---|---|---|
| 速度增强范围 | 均匀分布 U(0.9,1.1) | 均匀分布 U(0.5,2.0) |
| 每窗增强激活概率 | 0.5 | 0.5 |
| 增强方式 | 各行人最后观测位置锚定；past 与目标同时变换 | 相同 |
| 反射、随机数抽样顺序 | 原实现 | 相同 |
| 模型/参数量 | B0 / 295474 | 相同 |
| 损失 | 原 ModeQueryLoss + 0.20 覆盖辅助项 | 相同 |
| batch / clip | 64 / 5 | 相同 |
| AdamW | lr 0.00025，wd 0.0005 | 相同 |
| 调度 | 1 轮 warmup，64 轮独立 cosine | 相同 |
| EMA / 输出 | 0.995，固定最终轮次 | 相同 |

**替换范围，不叠加第二次缩放。** 代码不在已有 0.9–1.1 增强外再乘一个 0.5–2.0。也不加入旋转、未来弯曲、T1 损失或 E3，以免混入多个变化。

采用与原实现相同的普通均匀分布，便于只改两个边界。U(0.5,2.0) 的均值是 1.25，不是 1；增强激活概率为 0.5 时，混合尺度均值为 1.125。因此本项同时增加速度范围与平均增强速度，不能解释成纯粹“范围宽度”的消融。若后续要区分对数对称分布或均值漂移，须另立实验，本轮不自动加做。

空间交互也有边界：所有行人共用一个倍率，并保留各自最后位置，但更早的相对几何会变化。宽增强未必有益，可能使训练分布偏离真实交互，或伤害慢速和转向窗口；需要完整保留这些负结果。

## 实现与执行约束

`speed_aug_adapter.py` 在单个训练进程内临时替换 `baseline_factory.AUGMENT` 的两个速度边界，再调用原 `Trainer.step()`；退出或异常均恢复原配置对象，不修改旧源码或其文件。模型结构、数据读取、损失和优化步骤直接复用原实现。

使用 seed42，与原 B0 初始化一致；原加载器生成器、反射等抽样调用数保持相同。最终批次 ID 散列链必须与对照一致，不能只凭“seed 相同”宣称训练数据顺序一致。CPU 合成预检覆盖原 B0 初始化相同、实际训练器中途恢复后所有状态完全相同、推理对未来标签改动不敏感；GPU 启动前再验证目标设备。

启动需同时满足：DIAG 的 DONE 输出完整性核验通过，DECISION 与当前输入合同一致，状态为 `ELIGIBLE_EXPLORATORY`。不提供跳过失败条件的默认选项。通过条件仅代表这次训练值得探索，实际启动仍是单独手动操作。

执行单路，不再训练另一组 B0，不自动补 seed43，不自动跑 HOTEL 增强，不继续搁置的 COMBO 或旧五折。

## 评价与判断

训练完成后固定最终 EMA，在原 ETH 验证子集和 ETH 测试集评价。**主要比较使用原始输入，不叠加测试时速度归一化。** 这样衡量的是训练增强本身。两者叠加属于另一个问题，本轮不自动进行。

保留与 DIAG 相同的独立 minADE/minFDE、同候选覆盖、Top1、p95、原 stable/transition/change、训练速度分界、机动类型与交叉分组。验证集结果描述性保留，不选择中间最好 checkpoint，也不看测试结果追加轮数。

固定整体结论：minADE 和 minFDE 相对已有 B0 **同时下降至少 2%**，标记 `PROMISING_SINGLE_SEED`；否则 `NO_CLEAR_JOINT_GAIN`，并报告改善与恶化的具体指标。高速是否改善、低速是否退步、change 是否受损、尾部是否变差必须与整体一起呈现；不以单一正结果覆盖其他代价。

即使通过，也不自动替换 baseline，不宣称五折有效或统计显著，不将一个 seed 推广为稳定结论。ETH/HOTEL 已用于方法开发；保持探索性质，后续独立确认另行安排。
