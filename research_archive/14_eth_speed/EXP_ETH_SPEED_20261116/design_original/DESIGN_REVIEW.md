# 设计审查与解释边界

本轮按 academic-research-suite 的研究方法设计与反方审查思路，针对本机已有实验作设计审查，不开展外部文献综述或模型效果确认。中文说明按 avoid-zh-ai-coinage 的原则保留条件、单位与技术含义，避免把探索结果写成因果定论。

| 容易误判的地方 | 设计处理 | 仍然存在的限制 |
|---|---|---|
| 看到 ETH 快，就认定速度导致失败 | 先核原始标签链；运动缩放与反向缩放作对照；HOTEL 同做 | 上游标定仍未独立验证 |
| 在测试集选最好缩放比 | 只用各折 95% 训练观测拟合 q50/q90，主规则固定 | 已有 ETH 结果曾参与提出假设，属探索 |
| 缩小坐标后直接算更小误差 | 20 条候选逆变换回原世界坐标，与原 future 评价 | 非线性模型对尺度本来就可能敏感 |
| 速度缩放改变了邻居距离 | 主条件保留各行人最后位置，另做整体场景缩放 | 历史交互几何仍有变化 |
| 原始单位与视频时间混淆 | 区分标签编号与视频帧，检查 25fps 与每 10 帧取样 | 没有原始对齐证据不能完全证明时间标定 |
| 低速被高均值改善掩盖 | 固定训练分界，输出低/中/高及速度×机动 | 小组样本和窗口相关性限制推断 |
| 未来标签泄漏 | 缩放函数只接收 past/profile；推理只传 past/num_valid/ids | 机动标签本身事后使用 future，不能部署用于选择变换 |
| 增强效果与预算混淆 | E64 seed42、相同 95% 索引、复用匹配 B0 | 只有一个 seed，不评估训练随机性 |
| 范围增强被当作纯宽度消融 | 明确 U(0.5,2.0) 的均值漂移与混合概率 | 不区分范围和均值各自贡献 |
| 程序自动开出昂贵训练 | 诊断只输出建议，aug 手动独立启动且检查条件 | 用户仍需读结果后决定是否执行 |
| 退出 GPT 后停止 | 用 Windows 任务计划程序手动后台执行 | 关机/睡眠后不计算，恢复须手动启动 |

交付评估：设计与代码可以进入目标设备预检和正式审核阶段。此判断不是 GPU 实测通过、数据审核通过或假设成立的替代品。正式诊断与增强均未执行，结果栏不得填写成 PASS 或改善。
