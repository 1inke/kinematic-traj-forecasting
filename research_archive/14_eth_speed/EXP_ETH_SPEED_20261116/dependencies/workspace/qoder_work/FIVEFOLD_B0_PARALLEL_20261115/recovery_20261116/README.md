# Two-slot recovery, 2026-11-16

User authorized continuing in parallel after a WinError 5 monitor publication failure.
The adapter retains the sealed original trainer, contracts, budgets, seeds, data and
max-two scheduler. It installs unique temporary JSON files and bounded retries in
both controller and scientific children. Only CURRENT/CHILD_STATE monitoring files
may fall back to a status mirror after persistent Windows sharing/access errors.
Scientific/checkpoint/decision/DONE receipts still fail on persistent errors.

Use START.cmd, STATUS.cmd and PAUSE.cmd in this directory. START is an on-demand,
unlimited-duration Windows scheduled task and does not depend on Codex staying open.
It has no automatic triggers. The shared original mutex prevents duplicate owners;
the original Windows Job Object still stops children if their owner dies. Completed
budget runs are verified and reused; the two ETH final runs resume their complete
epoch checkpoints. Source manifests and original failure evidence remain intact.

Canonical status stays in ../standalone and in the original execution directory.
On persistent monitor locks, status_mirror contains the latest attempted values and
warnings contains per-process JSONL diagnostics. Check actual timestamps and worker
processes if canonical status is stale. The adapter's SOURCE_MANIFEST seals the
unchanged original manifest and this extension before launch and before success.
