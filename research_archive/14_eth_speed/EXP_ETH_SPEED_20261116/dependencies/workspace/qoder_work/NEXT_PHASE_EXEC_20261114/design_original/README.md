# 下一阶段实验设计：噪声基线 → 曲线解码 / 集合协同修正 → 训练方法

2026-11-14｜**DESIGN_ONLY**：本目录只有设计和代码，没有训练、模型前向，也没有改动任何旧结果。

## 为什么是这个顺序

11月以来的 U/D、DGeo、Q、DPP/CVAE 系列都被同两道门判为 FAIL：一道是“旧成功丢失 ≤1%”，另一道是“五项运动学指标 ≤ native×1.01”。已有证据显示，这两道门本身可能不可达：

- **丢失门**：CVAE 的 accuracy-only 与 accuracy+DPP 两臂初值、数据顺序完全相同，只差一个后来证实无增量的项，两者成功集合之间仍互相丢失 11–15%。任何重新训练的模型都可能有这个量级的“丢失”，它反映的是训练随机性，而不是方法伤害。
- **运动门**：fit-GT 的内部加速度均值是 0.170 m/s²，B0 只有 0.071（因为分段线性，大部分时间步速度恒定）；接续加速度 B0 是 0.68，GT 是 0.17。以 native+1% 为上限，GT 自己也会超出约 140%。

因此 **E1 先测出噪声地板和训练预算**，在任何新方法跑之前把新判定规则 `E2E_V2` 封存。E2、E3、E4 是三组互相独立的单因素实验，都以同预算、同 seed 的 B0 为对照，可以并行做。

```
E1 噪声基线 + 训练预算 ──► 封存 E2E_V2 判定合同
        │
        ├─► E2 运动学连续曲线解码（锚点不变，只换连接方式）
        ├─► E3 几何级候选集合协同修正（生成后一层集合注意力）
        └─► E4 训练方法三因素（软 WTA / change 加权 / 未来转向增强）
                │
                └─► F 胜出因素组合 + 标准 ETH/UCY 五折（之后另立设计）
```

## 共同协议（E2–E4 全部适用）

- **数据**：C0 的 fit 21,719 窗训练，dev 4,753 窗评价；分组 stable/transition/change 沿用 C0（未来变化分数，只用于评价和训练损失，永远不作模型输入）。
- **训练**：预算 E\* 由 E1 决定，batch 64，AdamW 2.5e-4/wd 5e-4，1 epoch warmup + cosine 到 E\*，固定取最终 EMA(0.995)，不按 dev 选 checkpoint。
- **seed**：42/43/44。同一 seed 下各臂共享参数的初值逐张量相同；新增模块在 `torch.random.fork_rng` 内构造，不扰动全局 RNG（因此 dropout/增强流也配对）。
- **B0 对照**：直接复用 E1 中预算为 E\*、seed 42/43/44 的 B0 运行，不重复训练。
- **导出**：每个模型的 dev（和 fit）输出保存为 `paths[N,20,12,2]`（世界坐标）、`logits[N,20]`、`ids[N]`，供 `exchange_null.py` 读取。

### E2E_V2 判定规则（E1 结束后填入数值并封存）

**信号**：3 个 seed 的配对差均值超过 2σ_null/√3（σ_null 为 E1 测得的同配置覆盖率差异标准差，按组），并且 3 个 seed 符号一致。同时报告整 track bootstrap 区间（沿用现有统计机器），但单 seed 不作显著性。

**伤害**（任一触发即“有伤害”）：
1. 超额丢失：方法对同 seed B0 的丢失率减去 E1 的 B0–B0 平均丢失率，超过容差 tol。tol = max(3pp, 2×E1 丢失率标准差)，按组计算；这条规则在看到任何方法输出之前固定。
2. 任一组覆盖率出现负向“信号”。
3. 运动远离 GT：对加速度均值、jerk 均值、接续加速度均值、速度 p95，计算 |log(模型/GT)|（J-oracle 候选对自身 GT 窗，以及全部 K20 对 fit-GT 参照）。比 B0 增加超过 0.05（约远离 GT 5%）算伤害。
4. 尾部：C0 的 p99.5 超阈率比 B0 增加超过 1pp（沿用）。

**旧门**：`LEGACY_SHADOW` 原样计算、原样报告（丢失 ≤1%、五项 motion ≤1.01×native、change ADE/FDE 各 5% 等），但不作为 E2–E4 的晋级依据。论文里两套都写，并用 E1 的结果说明为什么换。
