# EXP-REFINE-PRED 设计：迭代细化是否在低可预测窗口上收缩覆盖（零训练五折冻结重放）

Nov 23, 2026 · @akaza

## 一、一页结论

本实验不训练任何模型。它在五折上重放已训练的多层解码器（O-conf+E0、O-conf+QFL），比较同一模型第 0 层和第 3 层的输出，回答三个问题：

1. **Q1 规律是否普遍**：细化让"减速"窗口变差、让"匀速"窗口变好，这个现象在 UNIV、HOTEL、ZARA02 上是否也成立？
2. **Q2 能否从观测中识别**：是否存在只用历史的代理量，能提前找出"细化会有害"的窗口？
3. **Q3 机制**：变差是否伴随候选集合在纵向（沿行进方向）上的收缩？

**运行量**：五折共 17 个检查点 × 2 臂 = 34 次推理，不训练。ETH、ZARA01 已在 archive 28 重放过，但当时没有保存坐标衍生量，所以重新推理一次，并与 archive 28 的逐窗指标核对。

**预演已经显示一个关键问题**（第八节）：按未来机动分组，两折都是"减速变差、匀速变好"；但按观测分组，两折方向相反。所以 Q2 是整个实验的关键：它决定后续训练设计走"按可预测性门控细化"，还是走"对所有窗口保留纵向不确定性"。

**四种结局**（判据见第七节）：

- `GATED_REFINE`：规律普遍，且有观测代理能识别 → 设计按可预测性门控的细化。
- `PRESERVE_LONGITUDINAL`：规律普遍、确有纵向收缩，但没有代理能识别 → 设计不需要路由的约束：细化不得收缩纵向散布。
- `REDIAGNOSE`：规律普遍，但没有纵向收缩 → 机制不明，先做诊断。
- `STOP`：新增三折中不足两折成立 → 只是 ETH/ZARA01 的现象，停止这条线。

这是诊断性的相关研究，不能产生因果结论（第九节第 4 项）。

## 三、假设与预注册预测

核心假设：迭代细化把候选拉向训练集中最常见的延续方式。未来可预测时这是好事；未来在纵向上不可知时（是否减速），它会收缩覆盖。

- **正题**：DETR / ModeSeq 式的多层细化，每一层都把候选往真值方向推。
- **反题**（待本实验确认普遍性）：在纵向不可知的窗口上，每一层都让集合更集中在匀速延续附近，最好候选反而变远。
- **合题候选**：按可预测性控制细化力度（需要路由），或者细化不得收缩纵向散布（不需要路由）。本实验只决定走哪一条，不实现它们。

**预注册预测**（ETH、ZARA01 已看过，只作探索；UNIV、HOTEL、ZARA02 为确认折）：

1. **P1**：在未来标签为 `deceleration` 的窗口上，末层相对第 0 层的 minFDE 变差；在标签为 `steady` 的窗口上变好。两个臂方向相同。`stop` 单独报告，不并入减速组：预演中 ZARA01 的 `stop` 组反而变好。
2. **P2**：受害程度随观测速度升高而增加，随观测速度比（后 3 步 / 前 4 步）降低而增加。预演和 DECEL-DIAG 提示，很可能没有一个代理能达到第七节的门槛；这是预先写下的预期，不影响判据。
3. **P3**：在 `deceleration` 窗口上，末层候选终点的纵向散布小于第 0 层，且收缩比例大于 `steady` 窗口。

## 五、分组与代理量定义

所有分组分为三类：只用于评价的未来标签、只用观测的代理量（主分析）、来自模型自身输出的代理量（次要，有同义反复风险）。观测为 8 点、间隔 0.4 s，共 7 步位移。

### 5.1 未来标签（只用于评价，绝不进入代理量）

沿用 `eth_speed_math.maneuver_labels()`（archive 27 `code/sealed/eth_speed_math.py`），判定顺序与代码一致：

- 未来速度比 = 未来 12 步平均速度 / max(观测平均速度, 0.1 m/s)；≤ 0.8 为 `deceleration`，≥ 1.25 为 `acceleration`。
- 观测末 3 步方向与"观测末点→未来终点"方向的夹角 ≥ 30° 为 `turn`；同时满足变速为 `turn_and_speed`。
- 观测平均速度 ≥ 0.1 且未来 < 0.1 为 `stop`；观测 < 0.1 且未来 ≥ 0.1 为 `start`；两者都 < 0.1 为 `stationary`；其余为 `steady`。

### 5.2 观测代理量（主分析，预注册 4 个）

| 代号 | 定义 | 固定阈值 | 代码依据 |
| --- | --- | --- | --- |
| X1 观测速度 | 7 步位移长度均值 / 0.4 s | > 1.3 m/s 为高速 | `observed_speed()`；`frozen_replay/run.py` 中 `fast = speed > 1.3` |
| X2 观测速度比 | 后 3 步平均速度 / max(前 4 步平均速度, 0.1 m/s) | ≤ 0.85 为观测减速 | DECEL-DIAG 规则（`decel_followup/run.py` 第 142 行） |
| X3 观测转向角 | 前 4 步平均位移与后 3 步平均位移的夹角（度）；任一向量长度 ≤ 0.03 m 时记为 0 | 无，只用三分位 | 新增；0.03 m 沿用 `decel_followup` 的方向长度下限 |
| X4 路径效率 | 净位移长度 / 7 步位移长度之和 | 无，只用三分位 | `advisor_eval.groups()` 中 `eff` |

连续代理量按每折测试窗口的三分位分为低、中、高三档。只用观测量、不用未来，不构成信息泄漏。

### 5.3 模型输出代理量（次要分析）

- **X5 第 0 层纵向散布**：20 个候选终点在观测方向（后 3 步平均位移的单位向量）上投影的标准差；方向长度 ≤ 0.03 m 的窗口排除。
- **X6 第 0 层置信度熵**：20 个 logit 的 softmax 熵。

### 5.4 结果量

- **层间变化**：先对同一窗口的各 seed 取平均，再计算 Δ = 末层 minFDE − 第 0 层 minFDE。组内报告相对变化 ΣΔ / Σ(第 0 层 minFDE)。
- **受害窗口**：Δ > 0.10 m；为 Q2 的 AUROC 提供二元标签，同时报告 Δ 与代理量的 Spearman 相关。
- **纵向收缩比**：末层 X5 / 第 0 层 X5，取组内中位数；横向同口径报告。

## 六、指标与统计

独立单位是行人轨迹，不是窗口。所有区间都用按轨迹聚类的 bootstrap。

- **聚合顺序**：同一窗口先对各 seed 取平均，再按轨迹聚类。ETH 有 5 个 seed，其余折 3 个。
- **Bootstrap**：重抽样 4,000 次，随机数种子 20261124，按轨迹有放回抽样，统计量为比值 ΣΔ / Σ(第 0 层 minFDE)。
- **依赖结构报告**：每折每组报告窗口数、轨迹数，以及前 10 条轨迹占该组 ΣΔ 的比例。
- **敏感性**：UNIV 有两个录制（students001、students003），做逐录制留一。HOTEL、ZARA02 各只有一个录制，改为去掉 Δ 贡献最大的 10 条轨迹后重算。
- **最小组**：窗口少于 30 或轨迹少于 10 的组标为"小组"，只报告，不计入判据。
- **Q2 的度量**：X1–X4 对"受害窗口"的 AUROC（方向预先定为 X1 越高、X2 越低、X3 越大、X4 越低越容易受害），以及高三分位组与低三分位组相对变化的差。同时计算未来标签 `deceleration` 对受害窗口的 AUROC，作为参照上限。
- **多重比较**：P1 用跨折一致性规则判定，每折 95% 区间。Q2 的 4 个主代理量用 98.75% 区间（Bonferroni，4 个）；X5、X6 标为次要，用 95% 区间，不进入判据。
- **主臂**：O-conf+E0 为主，O-conf+QFL 只检查方向是否一致。

## 九、设计自检（八项）

**1. 干预隔离**

- 干预是"取第 3 层输出而不是第 0 层"，两者来自同一次前向、同一输入。除了目标量，还一起变了：三层细化、rank 嵌入、因果掩码、层间按置信度重排，以及置信度 logit。这些都属于"细化"这个整体，本实验不拆分。
- 操纵检查①：重放指标与回执差值 ≤ 5e-4。已有重放的最大偏差为 3.1e-8（ETH E0 s42）【已核实】。
- 操纵检查②：minFDE 与排序无关，同层置信度顺序与风险顺序的 minFDE 必须逐窗完全相同。已有 16 次重放全部满足【已核实】。
- 操纵检查③：第 0 层到第 3 层的候选终点移动量中位数 ≥ 0.02 m（沿用 archive 27 的 MC6 门槛），否则层间比较没有意义。

**2. 同义反复**

- 未来标签只用于评价，代码上与代理量分开计算。
- X5、X6 来自模型自己的第 0 层输出，而 Δ 也来自同一模型，属于"按模型自身输出分箱"，所以只作次要分析，不进入判据。
- C2 的门槛 0.60 和 P1 的分组都参考了 ETH、ZARA01，所以判据只在 UNIV、HOTEL、ZARA02 上结算。
- 三分位用测试窗口的观测量计算，不用未来，不构成在同一数据上选参。
- 相对变化用比值 ΣΔ / Σ(第 0 层 minFDE)，避免小误差窗口放大百分比。

**3. 依赖结构**：以轨迹为独立单位，报告轨迹数和前 10 条占比，用轨迹聚类 bootstrap；UNIV 做逐录制留一，HOTEL、ZARA02 去掉贡献最大的 10 条轨迹。预演因缺少轨迹编号暂用 15 窗分块，正式分析不用这个口径。

**4. 相关≠因果**：本实验属于诊断性的相关研究。它只说明"哪类窗口上末层输出比第 0 层差"，不说明"细化训练导致了收缩"，也不说明门控或约束就能修好。因果结论要等后续的训练干预实验。

**6. 预演**：已在第八节完成。限制：只能预演 X1，X2–X6 需要坐标。

**7. 非预期原因及排除方法**

| 结果 | 可能的非预期原因 | 如何排除 |
| --- | --- | --- |
| C1 通过 | `deceleration` 标签与高观测速度相关，变差其实是速度效应 | 在 X1 的同一三分位内，再比较 `deceleration` 与 `steady` |

| C2 通过 | 代理量实际反映的是场景或录制差异，而不是可预测性 | UNIV 在录制内分别计算 AUROC；二者差异大则不采信 |

**8. 混杂**

- 两个臂的损失不同（E0 与 QFL）：QFL 只用来检查方向是否一致，不合并。
- seed 数不同（ETH 5 个，其余 3 个）：另外报告逐 seed 的符号一致性。
- 硬件：ZARA02 seed 44 在本机训练，其余在 L4：ZARA02 另报去掉 seed 44 的结果。
- 折大小差异很大（ETH 364 窗，UNIV 24,334 窗）：只按折报告和计折数，不合并成一个平均数。
