# E1：噪声基线与训练预算

## 要回答的问题

| 编号 | 问题 | 为什么重要 |
|---|---|---|
| Q1 | 同一配置、不同 seed 的两个 B0 之间，成功集合交换（救回/丢失）有多大？覆盖率、minADE 差异的标准差是多少？ | 这是所有“方法 vs B0”比较的零假设地板 |
| Q2 | B0 对 B0 能否通过旧的“丢失 ≤1%”门？ | 若不能，说明旧门在定义上不可达 |
| Q3 | 交换主要来自初始化，还是来自数据顺序？ | 决定能否通过固定顺序来降低比较噪声 |
| Q4 | 同 seed 重跑是否逐位相同？ | 确定是否存在 GPU 非确定性这一层噪声 |
| Q5 | 8 epoch 是否已经饱和？ | 零初始化的新模块在 8 epoch、cosine 到 0 的情况下，有效更新很少 |
| Q6 | B0 的运动学离 GT 有多远？ | 给 E2 提供基线，也给论文提供换运动判定的依据 |

## E1-A 噪声基线（当前 8 epoch 预算，全 FIT 训练，dev 评价）

| 运行 | init seed | order seed | 用途 |
|---|---:|---:|---|
| 已有 B0 | 42 | 42 | — |
| A1–A4 | 43, 44, 45, 46 | 同 init | 5 个独立 B0，得到 10 对 / 20 个有向对 |
| A5 | 42 | 43 | 只换顺序 |
| A6 | 43 | 42 | 只换初始化 |
| A7 | 42 | 42 | 重跑，检查确定性 |

**init/order 的精确定义**：init seed 通过 `make_model(seed)` 控制全局 RNG，因此也决定 dropout 和增强的随机流；order seed 只控制 `Trainer.generator`，即 batch 顺序。所以 A5/A6 分解的是“batch 顺序”与“初值 + 随机流”两部分，不是更细的拆分。

**需要的代码改动（最小）**：
```python
# train_core.Trainer.__init__ 增加 order_seed=None
self.generator = torch.Generator().manual_seed(seed if order_seed is None else order_seed)
# 训练结束后导出
paths, logits = infer(trainer.ema.module, dev)
np.savez_compressed(out/'dev_pred.npz', paths=paths, logits=logits, ids=dev['ids'])
```

**分析**：
```
python -I code/exchange_null.py --data C0/dev.npz \
  --ref B0_s42.npz B0_s43.npz B0_s44.npz B0_s45.npz B0_s46.npz \
  --method order_only A5.npz --method init_only A6.npz --method rerun A7.npz \
  --motion-ref C0/MOTION_REFERENCE.json --out E1/E1A_NULL.json
```
注意：`--method` 的文件和 `--ref` 按位置配对，A5/A6/A7 都应和 seed42 的 B0 比较，所以第一个 `--ref` 必须是 seed42。

**按组报告**：
- 20 个有向对的丢失率均值、标准差、最小/最大值。
- 覆盖率差异的标准差 σ_null（单位 pp）。
- 旧门（丢失 ≤1%）的通过比例。
- A5、A6 各自的丢失率；A7 是否逐位相同。
- B0 的 `oracle_vs_GT` 和 `allK20_vs_fitGT`：加速度均值、jerk 均值、接续加速度、速度 p95 的比值与 |log 比值|。

## E1-B 训练饱和曲线（不使用 dev）

1. `make_calib_split.py`：按 SHA256 排序选出 FIT 15% 的整条 target track 作为 CALIB，其余为 FIT85。只按身份切分，不看任何标签。
2. 在 FIT85 上训练 B0，E ∈ {8, 16, 32, 64}，seed 42/43，共 8 次。每次都是 warmup + cosine 到自己的 E（不是截断同一条曲线）。
3. 用各次的最终 EMA 在 CALIB 上评价 overall/change 覆盖率、minADE、minFDE；同时记录 FIT85 训练损失。E=64 那次额外保存每个 epoch 的 checkpoint，在 CALIB 上画学习曲线（仅作描述）。

**E\* 规则（预先固定）**：取 {8, 16, 32, 64} 中最小的 E，使得从 E 加倍到 2E 时，两 seed 平均的 CALIB overall minADE 相对改善 < 1%，且 change 覆盖率改善 < 1pp。若到 64 仍在改善，则 E\* = 64，并注明“可能仍未饱和”。

## E1-C 在 E\* 下重建 B0 参照，并封存合同

- 若 E\* = 8：E1-A 的 5 个 B0 直接作为参照和噪声地板。
- 若 E\* > 8：在全 FIT 上以 E\* 训练 B0，seed 42–46 共 5 次。这些运行既是 E2–E4 的 B0 对照（seed 42/43/44），也用来重测 E\* 下的噪声地板，因为更长的训练可能改变交换量。
- 把 E\*、各组 σ_null、平均丢失率、丢失率标准差、tol，以及 README 中的 E2E_V2 规则写入 `E2E_V2_CONTRACT.json`。**在任何 E2–E4 模型训练之前**记录它的 SHA。

## 结果怎么读（预先写下，避免事后解释）

| 观察 | 解读 |
|---|---|
| B0–B0 丢失率 ≫ 1%（例如 > 8%） | 旧丢失门不可达；此前“丢失超标”的 FAIL 需要按超额丢失重读（只作补充分析，不改旧判决） |
| A5 交换量接近 A1–A4 | 顺序是主要来源；以后同 seed 配对比较已控制了大部分噪声 |
| A6 交换量远大于 A5 | 初始化/随机流是主要来源 |
| A7 不逐位相同 | 存在非确定性；把 A7 的差异记为最低噪声层 |
| B0 的接续加速度比值 ≈ 4、内部加速度比值 ≈ 0.4 | 直接支持 E2 的动机 |
| E\* ≥ 32 | U/D、DGeo 等 8 epoch 结论应读作“预算不足下未见信号”；是否在 E\* 下重测其中某个（例如 D-Gate），留到 E2–E4 之后再决定 |

## 局限

- 5 个 seed 的地板估计很粗。10 对之间也不独立（共享运行），σ_null 只作描述性尺度，不作精确推断。
- CALIB 来自与 FIT 同一批 recording 的不同 track，只用于选预算，不作泛化证据。
